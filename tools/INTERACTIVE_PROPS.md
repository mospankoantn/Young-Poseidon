# Інтерактивні об'єкти та кидок зброї
Оновлено 19 вересня 2026 року.

## Геймплей
- Тризубець і спис створюються на середині висоти колізійної маски героя, біля руки. Лівий напрямок задає image_xscale; image_angle маски залишається 0. Це усуває зачіпання підлоги й подвійний розворот.
- Кнопка E (або перепризначена дія) запускає лише один камінь. Якщо кнопок поруч декілька, реагує найближча. Невдале натиснення під час падіння/перезарядження не витрачає кнопку. Показуються залишок каменів, падіння та відлік відновлення.
- Наступний камінь позначений стрілкою, пунктирною траєкторією і зоною падіння. Падіння перевіряє перешкоди маленькими кроками; один камінь завдає Тритону 10 шкоди не більше одного разу.
- Уламки не мають батьківства obj_platform. Після приземлення залишаються до трьох секунд, згасаючи протягом останньої секунди. Камені Тритона переходять у невидимий стан для повторної хвилі; звичайні уламки видаляються. Наявне відновлення хвилі через три секунди після вичерпання збережене.
- Хащі втрачають колізію одразу після початку зрубування і видаляються після затухання. Двері блокують прохід до відкриття ключем, після анімації колізія вимикається.
- Сталактит дає чотири камені, які з'являються під ним і зникають після приземлення. Брила потребує трьох ударів кайлом із короткою затримкою між ударами.
- Вагонетка тимчасово бере на себе позицію героя, не використовуючи ефект заморожування. E садить/висаджує, A/D або стрілки керують рухом; дія стрибка або Space дозволяє вистрибнути. Вихід можливий лише у вільне місце.
- Пліт переносить пасажира на фактичне зміщення після тертя, вирівнює ноги при погойдуванні та не притягує героя у стрибку. Рух із веслом збережений.
- Пошкодження колон, брили та бар'єра видно за тріщинами й смугою міцності. Мінотавр перевіряє стояння героя за фактичною колізійною межею колони.
- Правила координат чекпоїнта та маска obj_player не змінені. Чекпоїнт отримав нову графіку і не активується мертвим героєм.

## Ресурси
Усі спрайти згруповані в Спрайты / Interactive. Для статичних станів image_speed = 0, потрібний кадр обирає код.

| Sprite | Object | Кадри |
|---|---|---|
| spr_falling_rocks | obj_falling_rocks | цілий / уламки |
| spr_falling_stone | obj_falling_stone | цілий / уламки |
| spr_interactive_button | obj_interactive_button | піднята / натиснута |
| spr_mine_cart | obj_mine_cart | вагонетка |
| spr_minotaur_column | obj_minotaur_column | ціла / пошкоджена |
| spr_olympus_door | obj_olympus_door | закриті / відкриті |
| spr_raft | obj_raft | пліт |
| spr_rail | obj_rail | рейки |
| spr_stalactite | obj_stalactite | сталактити |
| spr_stone_boulder | obj_stone_boulder | брила |
| spr_thicket_platform | obj_thicket_platform | хащі |
| spr_uranus_barrier | obj_uranus_barrier | кам'яний завал |
| spr_checkpoint | obj_checkpoint | святилище |

Крім падаючих каменів, збережено старі явні spriteMaskId інтерактивних об'єктів. Двері отримали батьківство obj_platform для закритої колізії, пліт отримав obj_thin_platform для наявних правил стрибка/спуску.

Джерело графіки: Файли/Графіка/Інтерактивні об'єкти/interactive_props_source.png, 1536x1024. Створено через ImageGen, імпортовано tools/import_interactive_props.ps1 із перевіреними прямокутниками, видаленням кольорового фону та найближчою піксельною інтерполяцією. Короткий зміст запиту: атлас 4x4 у стилі піксельної грецької пригоди, 16 окремих станів каменів, кнопки з тризубцем, вагонетки, колони, дверей, плота, рейок, сталактитів, брили, хащів, завалу й святилища; без тексту, на однорідному пурпуровому фоні для імпорту. Це нова графіка, не перероблений скріншот.

## Перевірки
Windows, GameMaker Runtime 2026.0.0.23:
- tools/validate_player_animations.ps1: 312 YY, 298 ресурсів, формат/посилання та регресія спрайтів героя.
- tools/validate_interactive_props.ps1: 13 спрайтів, 18 прозорих кадрів, шари, sequence/tracks, resourceType/resourceVersion та посилання всіх Objects.
- tools/test_interactive_props.ps1: компіляція та Runner; кидки обох видів зброї в обидва боки, камені/кнопки/відновлення хвилі, уламки, хащі, двері, сталактити, вагонетка, повний цикл погойдування плота.
- tools/test_weapon_visuals.ps1: регресія зброї, підбору, анімацій і повернення снаряда.
- tools/test_player_death.ps1: смерть, керування, поворот, маска та відродження з чекпоїнтом/без нього.
- tools/test_menu_settings.ps1: меню, перепризначення клавіш, пауза, збереження/завантаження та налаштування між процесами.
- Зображення Файли/Графіка/Інтерактивні об'єкти/interactive_props_preview.png отримане з Draw GUI у Runner і перевірене візуально.

Тести запускаються на тимчасовій копії проєкту, не переписують сюжетні кімнати. Це не повне ручне проходження кампанії. Більшість пізніх інтерактивів досі потребує розміщення та балансування в сюжетних кімнатах; двері не запускають фінальну сцену. Збереження стану зруйнованих перешкод між сесіями не додавалось.
